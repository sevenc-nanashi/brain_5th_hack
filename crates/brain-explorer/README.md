# Explorer

第5世代 Brain 向けの読み取り専用ファイルエクスプローラー。
SD カード (`SD0:\`) と ROM (`ROM:\`) のフォルダーを移動し、
ファイルをテキスト／16進表示で閲覧し、選択したファイル・フォルダーをUSBでPCへ送信する。
Brain側のファイルへの書き込み・削除・実行は行わない。

## ビルド

リポジトリのルートで実行する。Rust の `armv7a-none-eabi` target と `llvm-objcopy-20` が必要。

```sh
rustup target add armv7a-none-eabi
cargo run -p reflex-cli -- build explorer
# または
make explorer
```

`target/explorer/APP/Explorer/` を SD カードの `APP/Explorer/` にコピーする。
`AppMain.bin` と空の `index.din`、同梱ライセンスを保持する。
`reflex deploy explorer <SDカードのパス>` でも配置できる。

## 操作

| 操作 | キー／タッチ |
| --- | --- |
| 一覧の選択 | 上下キー |
| フォルダー・ファイルを開く | 決定／右キー、行のタップ、Open |
| 前／次ページ | PageUp／PageDown、Prev／Next。内容表示中は上下キーも使用可 |
| テキスト／16進切替 | T、Text／Hex |
| 選択中のファイル・フォルダー／閲覧中のファイルをPCへ送信 | S、Send to PC |
| USBを切断して一覧・内容表示へ戻る | 送信画面でEsc、Disconnect / Back |
| 親フォルダー・一覧へ戻る | Esc／Backspace／左キー、Back |
| 一覧・現在ページの再読込 | R |
| 終了 | Storage 画面で Esc／Backspace／左キー、Exit |

タッチは同じ行・ボタンで離すと確定し、外へ移動すると取り消す。
キーの重複した押下通知は解放まで無視する。
親フォルダーへ戻ると、開いていたフォルダーを選択する。
読み取りに失敗した場合は画面下部にエラーを表示し、元の一覧・ページを保持する。

## Send to PC（実験的・V690_H1専用）

1. 更新したExplorerをSDカードへ配置する。PC側の受信スクリプトも同時に更新する（再開対応のBRNFILE4。旧受信器とは非互換）。
2. 通常のPCConnectを終了してExplorerを起動し、ファイルまたはフォルダーを選んで **S / Send to PC**。
3. USBケーブルを接続する。WSLではDRMモードへの切り替え後に再attachする。
   Windows側に捕まる場合は管理者PowerShellで `usbipd bind --force --busid 5-1`、
   続いて `usbipd attach --wsl --busid 5-1` を実行する。BUSIDは環境に合わせる。
4. Ubuntuで対象の `/dev/sgN` を確認して受信する。下記の `sg4` は例。

   ```sh
   sudo ruby scripts/usb-probe.rb probe /dev/sg4
   sudo ruby scripts/usb-receive.rb /dev/sg4 ./received.bin
   ```

   受信器はUSB ID `04dd:92e1`、revision `0103`、4096×512 bytesのDRM機器だけを扱う。
   通常のSD公開モードやマウント中の機器は拒否する。
5. PC側に `Saved ...` が出たら完了。Brain側でEscを押し、USB切断後に閲覧へ戻る。

フォルダーを選んだ場合は `--directory` を付け、まだ存在しない保存先を指定する。
選択したフォルダーの内容を、サブフォルダー・空フォルダー・空ファイルも含めて保存する。

```sh
sudo ruby scripts/usb-receive.rb --directory /dev/sg4 ./received-folder
```

全件を再開用ストリームへ受信・同期した後、一時フォルダーへ展開して指定先へ移す。
指定先が途中で作られた場合も上書きを拒否し、失敗時は再開用データを保持する。
ファイル名は元のバイト列を保持し、文字コード変換は行わない。
タイムスタンプ・元のパーミッションは保存しない。ファイルは0600、フォルダーは0700で作る。
`--directory` なしでフォルダーを受信すると、展開せず専用のBRNTREE1ストリームとして保存する。

保存先はPC側で指定する。
既存ファイルは上書きせず、一時ファイルへの受信・同期と
完了応答の確認後に公開する。失敗・中断時は完成ファイルを作らない。
`sudo` 経由の保存ファイルは呼び出し元ユーザーの所有にする。
送信画面のバイト数は読み出し済みの量で、`Received on PC` がPCからの受信確認を表す。
PC側の保存成否は `Saved ...` で確認する。

### 中断後の再開

同じ保存先・同じ `--directory` 指定で受信コマンドを再実行する。
途中データは `OUTPUT.brain-part/` に保持し、成功時だけ削除する。
受信プロセスだけを再起動した場合は、本体の待機中・完了画面から新しいセッションを開始できる。
ケーブルを抜いた場合や本体がエラー・タイムアウトした場合は、Escで戻り、
同じファイル／フォルダーを再度Send to PCで選ぶ。本体の再起動後も再開できる。

転送元パス・種別・総量を照合した後、保存済みの各64 KiBブロックをSHA-256で照合する。
本体は保存済み部分を読み直すが、USBでは32-byteのハッシュだけを返す。
一致した位置から残りを受信し、ブロックごとにPCのディスクへ同期する。
中断時の書きかけブロックは切り捨てて再受信する。照合不一致では自動上書きせず停止する。
やり直す場合は別の保存先を指定するか、受信器を止めて対応する `.brain-part/` を削除する。
同じ保存先への同時受信はロックで拒否する。

フォルダーは再開用ストリームと展開結果の両方を保存するため、最大で内容の約2倍の空き容量が必要。
展開中に中断した場合、再開時にストリームを照合してから展開をやり直す。
電源断後、完成先と `.brain-part/` の両方が残ることがある。完成先は上書きせず保持する。

### 転送方式

64 KiBずつDEFLATE level 1（zlib形式）で圧縮して転送し、PC側で展開して保存する。
圧縮にはno_std対応の[miniz_oxide](https://github.com/Frommi/miniz_oxide)を使用する。
セッションIDと圧縮前の位置を照合し、同じ要求と応答の重複を除外する。
USBパケットのチェックサムに加え、zlibの整合性と展開後の長さも検査する。
PC側は新しいデータを受信した直後には待機せず、未着時だけ5 ms待つ。
本体の要求確認はPEGの1 tickごとに行う。

PC側には、圧縮前の総量に対する受信進捗（%）と、最初の要求からの平均速度を表示する。

- `Raw`: 圧縮前の転送バイト数／総量と実効速度（KiB/s）。フォルダーでは名前・種別などのメタデータも含む。
- `USB`: DRMセクターの送受信量と転送速度（KiB/s）。512 bytes単位で、制御・再送も含む。
  USB物理層やSCSIコマンド自体のヘッダーは含まない。

圧縮しにくいファイルでは転送量が減らず、圧縮処理の分だけ遅くなる場合がある。
ファイル全体をメモリーには載せない。転送位置・合計サイズは64ビットで、
フォルダー全体の2 GiB制限はない。単一ファイルはファイルシステムAPIの32ビットサイズに合わせ、
4 GiB未満まで。送信時の4096件制限はなく、元の絶対パスは259 bytesまで。
転送中は他の閲覧操作を停止する。
送信前に件数・合計サイズを数え、送信時に再度列挙する。全件の一覧を保持せず、
本体で保持するディレクトリーハンドルとパスは階層の深さに比例する。
事前走査から転送完了まで、元のフォルダー・ファイル・SDカードを変更しない。
再開時には保存済み部分の変更も検出するが、転送中の変更を固定するスナップショットではない。
フォルダーの列挙順が変わった場合も照合不一致となり、先頭からの再受信が必要。
列挙APIのEOFとエラーを区別できない制限も残る。

PC側は応答を30秒待ち、同じ要求を最大2回再送する。Brain側は接続・要求を120秒待つ。
再試行するときはBrain側でEscを押してから、改めてSend to PCを選ぶ。
終了時はUSBを切断する。通常のSD公開へ戻すには純正PCConnectを起動する。

転送準備からUSB切断完了まで、純正PCConnectと同じ電源遷移許可ビットを無効にする。
USB切断完了後に、開始時に有効だったビットだけを復元する。
転送エラー・完了画面でも接続が残る間は抑止を継続するため、Escで切断して戻る。
USB切り替え前のファイル・フォルダー準備に失敗した場合は即座に復元する。
詳細は[電源API解析](../../docs/power.md)を参照。

実機では数十MiBの転送後、約4分でUSB切断と本体リセットが発生した報告がある。
電源遷移の抑止漏れを修正したが、リセット原因の確定と修正後の長時間転送は未確認。
ARMビルド、Clippy、ホスト上での送信処理と受信器の自己チェック
（空ファイル、チャンク境界、中断後の再開、保存済み部分の変更拒否、完了応答の紛失、
フォルダー再開、重複・分割応答、上書き拒否）は通過。
再開の自己チェックでは送信側のSourceとUSB firmwareをホスト用に置き換えている。
プロトコルは[USB解析メモ](../../docs/usb.md)を参照。

## 表示と制限

操作領域は800×480。共通の854×480描画バッファの左側だけを使用する。
フォルダーを先に、各種別内ではファイル名の生バイト順に並べる。
一覧は9行、テキストは64列×12行、16進表示は16バイト×16行。
ファイルはページごとに開いて必要な部分だけ読み、閉じる。
テキスト／16進切替は現在のバイト位置を保つ。Prevは実際に通ったページ位置へ戻る。

- 標準フォントはASCIIのみ。非ASCII・制御バイトは `\xNN` として表示し、元の名前のまま開く。
  日本語の字形・文字コード変換は未対応。テキスト内のLF/CRLFは改行、タブは4列区切りの空白として扱う。
- パスは259バイトまで。閲覧画面の一覧は4096件までで、上限を超えるとエラーにする。
  フォルダー送信にはこの一覧件数制限を適用しない。
- ファイルのシーク先は `i32::MAX` まで。2GiB以降の閲覧は未対応。
- ファイル名の表示が長い場合は省略する。一覧の選択名は下部にも表示する。
- ファイルシステムAPIはV690_H1の静的解析に基づく。実機動作は未確認。
  列挙APIはEOFとエラーを区別できず、カード取り外し時などに不完全な一覧となる可能性がある。

ABI・アドレス・戻り値の根拠は[ファイル操作 API](../../docs/filesystem.md)を参照。

## ホストプレビュー

Unixホストの実ディレクトリーをSD0として使用し、Storage・一覧・最初のファイルの
テキスト／16進画面をPPMへ出力する。入力は変更しない。プレビューのROMには接続しない。
出力ディレクトリー内の同名PPMは上書きする。

```sh
cargo run -p brain-explorer --example preview -- /path/to/input target/explorer-preview
cargo clippy -p brain-explorer --all-targets -- -D warnings
cargo clippy -p brain-explorer --features device --target armv7a-none-eabi -- -D warnings
```

実機ではSD0/ROMの一覧、ファイル種別とサイズ、フォルダー移動、ページ送り、
空ファイル、カード未挿入、キー・タッチ、終了後の復帰を確認する。
EOFと列挙エラーの区別はAPI側の制限として残る。

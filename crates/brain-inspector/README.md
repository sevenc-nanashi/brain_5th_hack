# Inspector

PW-H1 の画面領域と入力を確認する独立した Rust アプリ。
Reflex の PEG API を使用し、他のアプリやゲームデータは不要。

リポジトリのルートで実行する。

```sh
make inspector
```

`target/inspector/APP/Inspector/` を SD カードの `APP/Inspector/` にコピーする。
フォルダー内の `AppMain.bin` と空の `index.din` が必要。

## モードとロック

| キー         | モード   | 内容                                                               |
| ------------ | -------- | ------------------------------------------------------------------ |
| ホーム       | TEXT     | 英大文字・数字・記号を1倍／2倍／3倍、7色、白黒反転で表示（起動時） |
| 国語/漢字    | KEYS     | 押下・解放を含む直近16件のキー履歴。最新が上                       |
| 英和/和英    | TOUCH    | タッチ座標、押下・移動・解放、十字線                               |
| My辞書       | PIXELS   | タッチでカーソルを配置、方向キーで1px、Shift＋方向キーで10px移動   |
| 履歴         | AUDIO    | 単発・連続テスト音、再生状態・消費通知の確認                       |
| 一覧から選ぶ | SETTINGS | システムのウィンドウクリップ設定、画面矩形の確認                   |

画面切り替えは上段6キー `0x28A`〜`0x28F` を左から順に使用する。

Shift **単独で1秒以上押して離す**とロック／解除する。起動時は解除状態。
ロック中はモード切替・設定変更・Esc 終了を抑止し、キー履歴・タッチ・カーソル操作は継続する。
Shift 押下中に別のキーやタッチを受け取ると、その回のロック操作を取り消す。
Shift のリピートでは計時をリセットせず、離したときに一度だけ切り替える。
Shift の修飾フラグだけでは長押し判定せず、Shift 自体の押下・解放イベントを使う。

履歴は全モードで記録し、モード切替でも保持する。切替キーや Esc も記録対象。
ピクセル座標はパネル全体の x=0〜853、y=0〜479 に制限する。
ホスト UI に隠れる位置も計測できるよう、暫定の利用可能幅800pxでは制限しない。

## ウィンドウクリップ設定

一覧キーで設定画面を開き、左で OFF、右で ON にする。初期値は ON。
起動中のみ保持し、ファイルへは保存しない。ロック中の変更は無効。

ここでのウィンドウクリップは、本体の左から右へのドラッグで発動する機能。
描画範囲を制限する PEG の `mClip` とは別物。
ON では押下・移動・解放を従来の基底ハンドラーへ渡し、OFF では Inspector 内で消費する。
どちらでも座標の計測とカーソル操作は継続する。

この方式は **実機検証待ち**。独立した許可／禁止 API は未特定。
PCConnect の `AppMain.bin` では、`0x14b24`〜`0x14b28` が種別9を消費し、
`0x14de8`〜`0x14e14` が種別10/11を自前処理して基底へ渡していない。
この処理と「PC接続では発動しない」という実機報告から、同じイベント抑止方式を採用した。
アプリへ届く前にシステムがジェスチャーを認識している場合、この設定では抑止できない。

設定画面では SCREEN API、PM/WIN REAL・CLIENT・CLIP、直近の DRAW RECT も表示する。
これらの CLIP 数値は描画用矩形で、上記スイッチの状態を表すものではない。

## 入力とピクセル計測

キー履歴の KEY/FLAGS は16進、TYPE は10進。TYPE=9/33 を押下側、34を解放側として扱う。
Shift 有効時は `00000800` → `00000840` となり、`KMOD_SHIFT = 0x40` で判定する。

タッチの押下・解放は TYPE=10/11。ドラッグは TYPE=9、KEY=`0x8000`。
データの下位16bitがX、上位16bitがYで、例の `0x01d0030e` は X=782、Y=464。
Reflex の `TOUCH_MOVE_PARAM` と `MessageData.point` を使い、ドラッグはキー履歴に入れない。
タッチ移動に合わせて座標とカーソルを更新する。緑は押下・移動、オレンジは解放。

タッチ・ピクセル画面はパネル全体854×480、50px方眼、上下の目盛りは10px刻み。
紫線は暫定の利用可能幅800pxの右端（x=799）、黄色はその中心x=400、水色はパネルの中心。
ピクセル計測の方向キーはカーソルを動かす。従来の手動境界の移動操作は廃止した。

TEXT はアプリ内蔵の5×7ドットフォントの表示テストで、本体の日本語フォントは使用しない。

## 音声テスト

「履歴」キー（`0x28E`）で AUDIO TEST を開く。音量操作はホストの共通設定を変更する。

- `Q`: 選択サイズ2本分の単発音。32768バイトなら約1.49秒。補充通知には依存しない。
- `W`: 選択サイズのバッファと消費通知による補充で連続再生。
- 左右キー: 4096 / 8192 / 16384 / 32768バイトを選択（初期値4096）。変更時に再生停止し、Q/Wで再開する。ロック中は変更しない。
- `P`: 停止・ハンドル解放。ロック中でも停止可能。
- PageUp/PageDown: 音量を0〜9で変更する。Shift併用でも同じ。ロック中は変更しない。

音は11025Hz・16bit・ステレオの約344.5Hz矩形波。左右同じ、振幅は2048。
ロック中は再生開始を抑止する。モード変更・終了時も音声を停止し、停止を確認できない場合は音声画面に残る。

`CALL` は直近の操作と成功／失敗。
`STATUS` は状態取得 API の成功、`STATE` は生の動作状態、`MS` / `BYTE` は再生位置。
`EVENTS` は音声通知 (`0x107`) の数。`PARAM`（16進）/ `DATA`（10進）は最後の音声通知。
`ACTIVE` はホストの読み取り先index (`handle + 0x5c`)。
`CUR` はバッファ0/1の「カーソル/長さ」、`STAGING` は内部バッファ長。
`SUBMIT` は補充成功回数、`US` / `MAX` は補充APIの所要時間と最大値（マイクロ秒）。
Inspectorの矩形波は開始前に生成済みなので、この時間に音源合成は含まない。

内部バッファは4096バイト×2に固定し、左右キーで入力サイズだけを変更する。
`START` は開始直後・初回再補充前、`STALL` は最初の停止検知時の記録。
停止判定は従来通り、カーソルが `[0, 入力長]` または逆順で、再生位置も一定時間進まない場合。
`STALL` と元の `START` は自動再起動後も保持する。手動Q/Wまたはサイズ変更で記録をクリアする。
読み出しはホストの稼働中に順次行うため、厳密に同時点の値ではない。

履歴キー → 左右で入力サイズ選択 → W の順で、4096 / 8192 / 16384を比較する。
停止したら `START` / `STALL` の `ACTIVE`、`CUR`、`BYTE`、`PARAM`、`DATA` を記録する。
選択中の側が消費済み、反対側が未読ならホストの補充ループ停止の候補となる。
開始時には使い切った入力だけを再投入するため、SUBMITの初期値は入力サイズにより異なる。

Q/W/P は大文字・小文字の両方に対応する。数字入力モードの場合は「あA1/記号」でアルファベット入力へ切り替える。
無音時は `Q` と `W` のそれぞれで音の有無と上記の表示値を確認する。
これらは切り分け用の観測値であり、Doom の無音原因はまだ確定していない。

## 読み取り元と制限

矩形は `(left, top) - (right, bottom)` と幅×高さで表示し、PEG の右下端は包含座標として計算する。
オブジェクト内のオフセットは REAL=`+0x0c`、CLIENT=`+0x14`、CLIP=`+0x1c`。
V690_H1 の起動規約と既存の矩形配置に基づく生値であり、これらの領域が
ホスト UI を完全に除外するかどうかは実機で比較する必要がある。

画面は PEG の Bitmap と Draw callback 経由で描画し、液晶へ直接書き込まない。
終了時にはタイマー・フォーカス・vtable を片付け、ホストへ終了を通知する。

```sh
cargo clippy -p brain-inspector --all-targets -- -D warnings
cargo clippy -p brain-inspector --features device --target armv7a-none-eabi -- -D warnings
```

実機の入力値・ホスト UI の境界・終了後の表示復旧は実機確認が必要。

音量表示はホスト設定の読み戻し値。FAIL は保存用音量の読み戻しが指定値と一致しないことを表す。
Streamの初期値は、実機で安定再生を確認した4096バイト（1本約93ms）。
Wの連続再生は実機確認済み。音量は純正アプリと同じ保存用APIに修正したが、再生中の反映と終了後の保持も実機確認済み。Doomも4096バイトへ変更済みだが発砲音は未確認。

INPUT は選択した入力サイズ、STAGING は実際の内部バッファ長。
4096バイトは安定再生を確認済み。2048バイトは以前に無音が発生した。今回の比較では内部長を4096に固定し、入力長だけを変える。改修後の組み合わせは実機未確認。

## Reflexへの移行

起動・ウィンドウ所有・Bitmap転送・終了は `#[reflex::main]` / `Application` に共通化した。
計測値と入力状態は `Inspector` が所有し、`raw_event` で生のキー種別や音声通知を受ける。
`before_draw` で無効矩形とホストの矩形を採取する。
クリップ許可中のタッチは `RedrawAndBubble` でホストにも渡す。
音声停止に失敗した場合は `can_exit` が終了を保留し、音声画面で再試行できる。
移行後のホスト再描画・終了・音声継続は実機確認待ち。

## Panicテスト

一覧キーで設定を開き、ロック解除状態でShift+Pを押す。
確認表示でYを押すと `Inspector: intentional panic test` のpanicを発生させる。
N・Del・Escでキャンセルでき、別モードへの移動やロックでも確認を解除する。
単独のP、キー解放、ロック中の操作では実行しない。
Reflexの `panic-qr` を有効にしており、メッセージ・発生位置とQRを表示して停止する。
テスト後は本体の再起動が必要。実機でのpanic画面表示は未確認。

Inspectorの全画面はReflexの共通ASCIIフォントを使用する。音声・キー履歴・設定・下部メニューは6×13の原寸表示、通常の表示は2倍。文字テストは1〜3倍で大文字・小文字を比較する。

## FPUテスト

一覧キー → `F` → 決定キーで実行する。ロック中は実行できない。
単精度・倍精度それぞれで `(1.5 + 2.25) * 2 / 3 = 2.5` を VFP 命令で計算し、
結果のビット列を照合する。倍精度は100万回繰り返し、`d0–d31` の値も検査する。
`PASS` は演算結果・レジスター値・演算後の FPSCR が期待値と一致したことを示す。
`D0-D31 BAD MASK` のビットNが1なら `dN` の値が不一致。`ELAPSED` は実行時間（μs）。

CPACR、実行前の FPEXC / FPSCR、MVFR0、CPSR を表示する。
CPACR が FPU アクセスを禁止している場合は `NO ACCESS` として実行しない。
FPEXC.EN はテスト中だけ有効にし、FPEXC / FPSCR と ABI の保存対象レジスターは復元する。
Inspector 全体の ABI と他アプリのソフトフロート設定は変更しない。

割り込みは禁止しないため、ループ中に発生した割り込みによるレジスター破損も検出対象になる。
ただし割り込みやタスク切替の発生回数は計測せず、`PASS` だけで全保存経路の正常性は保証しない。
実機実行は未確認。ファームウェアが想定と異なり命令例外などで停止した場合は再起動が必要。

## 操作バーテスト

一覧キー → `B` で OPERATION BAR を開く。ロック解除状態で操作する。

| キー | 操作 |
| ---- | ---- |
| C | 選択したボタンを生成して表示（初期値は3枠、下から決定・下・上） |
| D | 破棄 |
| S | control `0x0a`（両方の表示条件を有効化） |
| Q / W | control `0x01` / `0x02` |
| E / R | control `0x04` / `0x08` |
| 上 / 下 | 編集する枠を選択 |
| 左 / 右 | 選択した枠のボタン種類を切り替え |
| O | 1列／2列の展開テストを切り替え |
| L | 暗色／明色の背景と対応画像を切り替え |
| T / Shift+T | 選択枠／現在の全枠の画像をランダムに変更 |
| PageUp / PageDown | 1列の枠数を増減（1列時1〜60、2列時1〜30） |

左右キーで、52×52の純正画像273件（共通218件＋辞書側55件）とRustロゴを選択できる。画像名と通常／押下IDを表示する。
Lはバー背景を薄灰色／暗色、区切りを黒／白に切り替える。対応画像のある枠は、隠れている枠も含めて置換する。対応のない画像とRustロゴは保持する。
`LIGHT_` で始まる画像が明色版。左右キーで個別にも選べる。生成済みなら再生成して反映し、未生成ならCで生成する。Lもロック中は無効。
2列テストはO → Cで生成し、右バー最下段の「開く」をタップする。生成済みならOだけで再生成する。
枠1を開閉専用にし、1列の枠数の2倍を登録する（開閉ボタンを含む）。「閉じる」または展開中の別ボタン操作で1列へ戻る設計。
枠1の左右キー・Tによる画像変更は抑止し、Shift+Tも開閉ボタンを除く。Lで開閉画像も明色／暗色へ切り替える。
2列への切替時に1列30枠を超えていれば30へ減らす。1列へ戻しても枠数は自動復元しないが、各枠の画像選択は保持する。
Oもロック中は無効。2列の実機での開閉・押下通知・画面復旧は未確認。

Tは現在と異なる画像を選ぶ。Shift+Tは現在の登録数（2列時は両列、開閉ボタン以外）だけ変更し、減らして隠れている枠は保持する。
枠どうしで同じ画像になることはある。ロック中は変更しない。
実機で3枠の場合は枠1が下、枠3が上と確認できたため、編集一覧も枠番号の降順で表示する。
上下キーはその画面位置に合わせて枠を選び、端では反対端へ循環する。
画像IDは `017C` が縦横切り替え（ROTATE）、`01A2` が電源（POWER）、
`0460` がホーム（HOME）、`0462` が決定（ENTER）と実機で確認済み。
通常画像には対応する押下画像を組み合わせる。`_PRESSED`・`_DISABLED`・`_SELECTED` と単独画像は押下時も同じ絵柄を表示する。`_DISABLED` は絵柄だけで、通知は無効にしない。生成済みならバーを再生成して表示するため、
表示フラグは `0x0a` に戻る。未生成なら選択だけ変更し、Cで反映する。
選択はモード移動や破棄後も起動中は保持する。ロック中は枠選択・種類変更を抑止する。
スロット数変更もロック中は抑止する。減らした枠の種類は保持し、増やすと復元する。
生成済みのスロット数変更も再生成して反映する。10枠以上では52×52画像より枠が小さくなる。並び・画像の欠け・タッチ範囲は実機未確認。
編集一覧は9枠ずつ表示し、上下キーで選択した枠を含むページへ切り替わる。
上限60はSharpLibの矩形領域（960バイト／1枠16バイト）に合わせた値で、実機で60枠の動作を保証するものではない。

画面上のボタンを押すと `EVENTS` が増え、`PARAM` に枠番号（1〜60）を表示する。
通知は種別 `0x10b` として受信し、キー操作や本体機能は実行しない。
`HANDLE` は生成結果、`SLOT … ITEM` は選択枠の登録ID、`CALL` / `RESULT` は直近のAPI呼び出しと生の戻り値。
`LAST FLAGS` は最後に渡した値で、現在の表示状態を読み戻した値ではない。
制御APIは変更がない場合にも0を返すため、0だけで失敗とは判定しない。
生成・項目登録の失敗時は再試行でき、登録途中の失敗でもバーを破棄する。
別モードへの移動・終了時にはバーを破棄する。
純正PCConnectと同様、種別7/8の通知でもcontrol `0x04` / `0x08` を呼ぶ。

Reflexの `operation_bar::raw` を使用する。V690_H1専用の未検証ABIで、
生成の第2・第4引数は `unknown1` / `unknown3` として公開し、この試験では両方0。
設定構造体の未確定フィールドも `unknown_*` として残す。
項目構造体は全形式を型にせず、PCConnectの0x220バイトの画像形式だけを使用する。
生成・破棄・表示切替・通知・終了後のホスト表示復旧は実機で確認すること。

### 自作Bitmap

左右キーで `RUST LOGO` を選び、Cで生成する。生成済みなら即座に反映する。
アプリ内のRGB565ピクセルを `operation_bar::Bitmap` で渡し、リソースIDを使わずに登録する。
通常時は白背景、押下時は背景を暗くした52×52のロゴ。画像の実機表示は未確認。
SharpLib `0x10fae8` は項目の `+0x20` にあるBitmapを読み、`0x10fb24` で内部画像へコピーする。
押下画像は `+0x40`。Bitmapはflags→bppの順で、既存 `peg::Bitmap` のフィールド順とは区別する。

素材はRust同梱の公式ロゴSVG。出典・ライセンスは配布物の `RUST-LOGO-LICENSE.txt` に同梱する。
グレースケール素材は次のコマンドで再生成でき、RGB565への変換はコンパイル時に行う。

```sh
convert -background white crates/brain-inspector/assets/rust-logo.svg \
  -alpha remove -alpha off -resize 44x44 -gravity center -extent 52x52 \
  -colorspace Gray -depth 8 gray:crates/brain-inspector/assets/rust-logo.gray
```

### 純正画像の定数

`reflex::operation_bar::image` に、`EDNewRes_Color.bin` 内の
`color_res_lib.bin` の218件と `color_res_dic.bin` の55件の52×52画像IDを公開する。
Inspectorは同モジュールの `ALL` を使用し、画像本体はROMから参照する。
画像のコピーをアプリへ同梱する必要はない。

例：`HOME` / `HOME_PRESSED`、`DELETE` / `DELETE_PRESSED`、
`SETTINGS` / `SETTINGS_PRESSED`、`ZOOM_IN` / `ZOOM_IN_PRESSED`。
名前は画像の見た目に基づき、キーコードや本体機能との対応を意味しない。
画像状態の名称とペアは抽出画像に基づく。追加画像の実機表示は未確認。

SetMenuから確認済みの6組も、SLIDESHOW、TEXT_SIZE、ABC_INPUT、
TEXT_LARGE、TEXT_SMALL、NUMERIC_INPUTとして選択できる。

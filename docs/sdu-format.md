# PW-H1 SDU の解析記録

`SH_DIC_UPDATE_V690_H1(1).SDU`（136,808,651 bytes）を直接解析した結果。
公式仕様ではなく、このサンプルとの一致を確認した範囲の記録。数値は特記しない限り little-endian。
他機種・他バージョンへの互換性は未確認。

## 全体構造

| 領域 | ファイル内オフセット | サイズ |
| --- | ---: | ---: |
| SDU ヘッダー | `0x00000000` | `0x8000` |
| updater（仮称） | `0x00008000` | `0xEC8CB` |
| boot（仮称） | `0x000F48CB` | `0x60000` |
| system（仮称） | `0x001548CB` | `0x19DC00` |
| 更新パッケージ列 | `0x002F24CB` | `0x7F86400` |

各領域は隙間なく連続し、合計がファイルサイズと一致する。
updater 領域は `0x73` との XOR によって ARM コードらしいバイト列や更新関連の文字列が見えるが、
完全な復号方式と構造は未確定。ツールでは加工せず保存する。
boot / system 領域には ARM コードらしいバイト列や SHARP の文字列がある。

## SDU ヘッダー

| 相対位置 | 型 | 内容 |
| --- | --- | --- |
| `0x00` | u32 | ヘッダー長 `0x8000` |
| `0x04` | u16 × 2 | ヘッダーチェックサムとそのビット反転 |
| `0x08` | u32 | SDU 全体のサイズ |
| `0x10` | u16 × 2 | updater のバイト和（mod 65536）とそのビット反転 |
| `0x1C` | NUL 終端文字列 | 機種 `PW-H1` |
| `0x7C` | u32 | updater 領域のサイズ |
| `0xB4` | u32 | boot 領域のサイズ |
| `0xD0` | u32 | system 領域のサイズ |
| `0xEC` | u32 | 更新パッケージ列のサイズ |

ヘッダーチェックサムは、チェックサム自身を含むヘッダー全体のバイト和 mod 65536 と一致する。
二つの u16 は互いのビット反転なので、チェックサム欄の 4 バイトの和は常に 510。
boot / system 単体のチェックサム位置は特定していない。

## 更新パッケージ

パッケージは `0x400` バイトのヘッダーとレコード列で構成される。

| 相対位置 | 型 | 内容 |
| --- | --- | --- |
| `0x00` | u32 | ヘッダー長 `0x400` |
| `0x04` | u32 | 種別 `1` |
| `0x08` | char[8] | 機種（NUL 終端） |
| `0x10` | char[8] | 更新後バージョン（NUL 終端） |
| `0x18` | char[8] | 更新前バージョン（NUL 終端） |
| `0x20` | u32 | レコード列のサイズ。ヘッダー自身を除く |
| `0x3FC` | u16 × 2 | ヘッダーチェックサムとそのビット反転 |

チェックサムの計算方法は SDU ヘッダーと同じ。
サンプルでは `0x002F24CB` に `1.80 → 3.30`、`0x06A69ACB` に `3.30 → 3.40` がある。

## ファイルレコード

| 相対位置 | 型 | 内容 |
| --- | --- | --- |
| `0x00` | u32 | ヘッダー長 `0x400` |
| `0x04` | u32 | 種別 `2` |
| `0x08` | char[0x208] | `ROM:\...` の NUL 終端パス（実際のフィールド上限は推定） |
| `0x210` | u32 | 格納されたデータの長さ |
| `0x214` | u32 | データのバイト和 mod 2³² |
| `0x218` | u32 | タイムスタンプと思われる値。生の数値として保存 |
| `0x224` | u32 | 第 2 のサイズ欄。action=1 の全サンプルで `0x210` と同じ |
| `0x228` | u32 | 第 2 のチェックサム欄。action=1 の全サンプルで `0x214` と同じ |
| `0x22C` | u32 | 操作種別（action） |
| `0x230` | u32 | 属性と思われる値。生の数値として保存 |
| `0x3FC` | u16 × 2 | ヘッダーチェックサムとそのビット反転 |
| `0x400` | byte[] | データ本体。次のレコードまで `0x200` バイト単位に切り上げ |

データのチェックサムはパディングを含めない。レコードヘッダーのチェックサムは上記と同じ。

| action | 件数 | 観測と扱い |
| --- | ---: | --- |
| `1` | 81 | ファイル本体あり。チェックサム検証後に展開 |
| `2` | 2 | 本体なし。削除指示と推測されるが、適用せず manifest に保存 |
| `3` | 1 | 本体なし。意味未確定。manifest に保存 |

action=3 は `ROM:\TELOP\KikutanEiken_2\KikutanEiken2.btbl` に対応する。
`0x214` は非ゼロだが本体がなく、通常のデータチェックサムとしては検証できない。

## 検証と制限

- 2 パッケージと 84 レコードを境界どおりに走査し、ファイル末尾との一致を確認。
- SDU ヘッダー、updater、86 個のパッケージ／レコードヘッダー、81 個の本体のチェックサムを検証。
- フォントには通常の TrueType ヘッダーがあり、`version.txt` は読めるテキスト。
- 7-Zip は途中の領域を FAT12 と認識するが、ファイル名・サイズが不自然で誤検出と判断。
- 本ツールは既知のレコードを切り出す。`.zxl`、`.zpbm` などの内部形式は展開しない。
- チェックサムは破損検出用の加算値であり、署名検証ではない。

未解明のフィールドは推測で補わず、元データを `header.bin` と各領域の `.bin` に残す。

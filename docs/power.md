# V690_H1 電源遷移の抑止 API

V690_H1 の `system.bin`、`SharpLib.bin`、純正 PCConnect の `AppMain.bin` を静的解析した記録。
関数名は仮称。公開入口は実行時アドレス、解析位置は各ファイルのオフセット。
実機での呼び出しは未検証。Reflex の公開 API にはまだ追加していない。
Explorer のUSB送信では、この入口を用いて転送準備から切断完了まで mask=7 を解除し、
終了時に開始前の有効ビットだけを復元する。送信中のエラーでは切断操作まで抑止を継続する。

## 公開入口と純正アプリの使用例

SharpLib の `0x84010080` は、次の C ABI に相当する。

```c
uint32_t power_mask(uint32_t mask, uint32_t enable);
```

- `enable = 0`: 指定した電源遷移許可ビットを解除する。
- `enable != 0`: 指定した許可ビットを設定する。
- 戻り値: 変更前に許可されていたビットのうち `mask` に含まれるもの。

PCConnect は `0x19cd0` の処理で `power_mask(7, 0)`、
対になる `0x19d40` の処理で `power_mask(7, 1)` を呼ぶ。
呼び出し先のサンク `0x19c2c` が `0x84010080` を参照する。
このため、純正アプリと同じ電源遷移抑止を行う入口は特定できた。
PCConnect は前後で別の control コマンドも実行するため、この関数だけで
PCConnect の電源・画面管理をすべて再現できるとは限らない。

アプリで利用する場合は、終了・キャンセル・転送エラーでも復元する必要がある。
単純に `7` を再設定すると元から無効だったビットまで有効になるので、
戻り値を保存して、そのビットだけを再設定する設計が候補となる。
これは共有状態のビット操作であり、参照カウント式ロックではない。
他の処理が同じビットを変更する場合の競合や異常終了時の復元は別途検討が必要。

## 実装の裏付け

SharpLib の公開入口 `0x10080` → `0xe6198` → `0xe6220` は、
system の control 入口 `0x600063c0` に次の引数を渡す。

```c
control(0x1001a, &mask, enable, &previous, 4, NULL);
```

このコマンドでは通常の入力サイズ欄が enable として使われる。
system の `0x8fc98`～`0x8fd90` はイベントフラグ群3を読み、
外部マスク `1, 2, 4, 8, 0x100` を内部ビット `1, 2, 4, 8, 0x10` に変換する。
enable が0なら AND による解除、非0なら OR による設定を行う。
SharpLib は control の失敗を戻り値として伝えないため、戻り値0だけで成功・失敗を判別できない。

system の電源遷移処理 `0xa69e8` は、この許可状態を参照して
`0xa6aa0` 以降の POWER DOWN 処理へ進むかを決める。

| 許可ビット | 判定される電源イベント |
| ---------- | ---------------------- |
| `1` | `0x80`、および下位9ビットが `0x102` の場合 |
| `2` | `0x08` |
| `4` | `0x10` |
| `8` | `0x04` |

イベント `0x60` に含まれるビットがある場合は通常の許可判定を迂回する。
したがって、mask=7 はすべての電源断を禁止するものではない。
各イベントと自動スリープ・電源キー・ふた操作との対応は未確定。
bit4 の再許可時には別途イベント `0x400` を送信するため、
タイマー関連の可能性があるが、自動スリープだけを止めるビットとはまだ断定しない。

関連入口 `0x840100dc` は control `0x1000f`、`0x840100f4` は `0x10010` を呼ぶ。
system 側ではそれぞれイベント `0x400`、`0x200` と `0x400` を送信する。
タイマーのリセット候補だが、周期呼び出しによるスリープ回避は未検証。

## 実機で確認すること

転送中の放置、電源キー、ふた操作、転送終了・キャンセル後の通常スリープを確認する。
バックライト消灯と本体スリープを区別し、mask=7 の各ビットを個別に照合する。
本記録の固定アドレスは V690_H1 用で、別ファームウェアには流用しない。

# 本体時計（V690_H1）

TIC-80の `tstamp()` はUnix秒を返すCの `time(NULL)` を使う。
ARM版ではNewlibの `_gettimeofday` が未実装で、`libnosys` のスタブに接続されていた。
`engine/runtime.c` で本体RTCの読み取りへ接続する。ゲーム用の `time()` は別系統で、従来どおり実行フレーム数から経過ミリ秒を返す。

## 公開入口と構造体

公開control入口 `0x600063c0` は `system.bin:0x3fc0` → `0x90a04`。
引数は `command, input, input_size, output, output_size, transferred`。
`command = 0x30013`、inputはnull、input_sizeは0、outputは16バイト、transferredはnullとする。
戻り値1が成功。読み取りだけを行い、本体時計は変更しない。

- `0x90328` の分岐から `0x9066c` へ進む。
- `0x90674` で出力長が16バイト以上であることを確認し、`0x90680` で `0x9fc88` を呼ぶ。
- `0x90694` で戻り値1を設定する。inputがnullなら時計の設定処理へ進まない。
- `0x9fc88` → `0x9fbac` はRTCカウンターを日時に変換する。`0x9fb18` はレジスターを二度読み、一致するまで再取得する。
- 出力は16-bit整数8個：年、月、曜日、日、時、分、秒、ミリ秒。年は西暦、月・日は1始まり。
  日付は `0x9f960`〜`0x9fa38`、時・分・秒・ミリ秒は `0x9fbac`〜`0x9fc84` で格納する。

## Unix時刻への変換

Newlibの既定タイムゾーンUTCで `mktime` により暦を変換し、本体の日時を日本時間（UTC+9）として9時間を引く。
RTC取得失敗・日時変換失敗は `_gettimeofday` のエラーとして返し、時刻0で代用しない。
フレーム数やFPSには依存せず、呼び出すたびにRTCを読む。

日本時間以外に本体時計を設定している場合のタイムゾーン切替は未対応。
ABIはファームウェアの命令列から確認したもの。実機時計との一致・秒の進行は実機での確認が必要。

# PW-H1 のアプリバイナリ

対象は V690_H1 の更新パッケージから取り出した 14 個の `AppMain.bin`。
公式仕様ではなく、命令列の逆アセンブルと複数ファイルの比較による解析結果。

## 概要

`AppMain.bin` は先頭から実行コードが始まる ARM little-endian のフラットなイメージ。
PE / ELF のような先頭ヘッダーはなく、ARM 命令と Thumb-2 命令が混在している。
実行コード・定数・初期化用のテーブル・圧縮された RAM 初期値が同じファイルに入る。
ファイル全体を ARM 命令として逆アセンブルすると、Thumb 部分やデータ領域を誤読する。

概念上の配置は次のとおり。ただし PE / ELF のセクション名が記録されているわけではない。

```text
AppMain.bin
  offset 0       ARM の起動処理
                 ARM / Thumb コード、定数、文字列など
                 Thumb の初期化ディスパッチャ
                 ゼロ初期化・伸長などの処理ルーチン
                 初期化テーブル
                 圧縮された RAM 初期値

RAM
  data_address   展開済みの初期値（.data 相当）
                 必要に応じて小さな隙間
  zero_address   ゼロ初期化領域（.bss 相当）
```

追加アプリが raw executable であることは、既存の
[boot4u](https://github.com/brain-hackers/boot4u) と
[Brain Hackers の第5世代ハック記録](https://scrapbox.io/brain-hackers/第5世代ハックの歴史)
とも一致する。後者には ARM の raw コードを `AppMain.bin` として起動した実験が記録されている。

## 先頭の起動処理

`RomanTyping/AppMain.bin` では次の命令がファイル先頭にある。
コメントの値はファイルオフセット、RAM アドレスを区別して記載した。

```asm
; file offset 0x00、ARM 状態
push {r4, lr}
mov  r4, r0
blx  thumb_initializer       ; file offset 0x22A00
ldr  r0, [pc, #12]           ; literal at file offset 0x20
str  r4, [r0]                ; RAM 0x86804924 に起動時の r0 を保存
ldr  r0, [r4, #8]            ; 起動引数の構造体から +8 の値を取得
pop  {r4, lr}
b    app_entry              ; file offset 0x229F8
```

`ATR_UG`、`FirstTOEIC`、`rekiken` では、保存したポインタを再読込して `+8` の値を渡し、
アプリ本体を `BL` で呼び、`POP {r4, pc}` で戻る形になっている。
引数の構造体の正確な型や `+8` の意味、API テーブルとの関係は未解明。

## 初期化テーブル

先頭 `BLX` の先には共通の Thumb ディスパッチャがある。
PC 相対の `MOVW / MOVT / ADD / SUB` でテーブルの先頭と末尾を求め、次を繰り返す。

1. 現在位置から signed 32-bit の相対ハンドラーアドレスを読む。
2. 現在位置を足したアドレスへ `BLX` する。bit 0 は Thumb 状態の指定。
3. 引数 `r0` はハンドラーアドレス欄の直後を指す。
4. ハンドラーが `r0` で返した位置を、次のエントリーの先頭とする。

**固定長の構造体配列ではない。** ハンドラーごとに引数の長さが異なる。
14 アプリでは、最初がゼロ初期化、次が圧縮データ展開。一部には引数なしの追加ハンドラーもある。
解析ツールは追加ハンドラーのアドレスを記録するが、その処理は再現しない。

### RomanTyping の例

| ファイル位置 | 値 | 意味 |
| --- | --- | --- |
| `0x22AC8` | `0xFFFFF833` | 相対ハンドラー。加算結果 `0x222FB` → Thumb コード `0x222FA` |
| `0x22ACC` | `0x314` | ゼロ初期化するバイト数 |
| `0x22AD0` | `0x86804890` | ゼロ初期化の RAM アドレス |
| `0x22AD4` | `0` | ゼロ初期化リストの終端 |
| `0x22AD8` | `0xFFFFFF79` | 相対ハンドラー。加算結果 `0x22A51` → Thumb コード `0x22A50` |
| `0x22ADC` | `0xC` | この欄から圧縮データまでの相対オフセット |
| `0x22AE0` | `0x1434` | 圧縮長を左に 1 bit シフトした値とフラグ |
| `0x22AE4` | `0x86800000` | 展開先の RAM アドレス |
| `0x22AE8` | … | 圧縮データ本体。`0xA1A` bytes |

この例では `0xA1A` bytes が `0x4890` bytes に伸長され、
`0x86800000..0x86804890` を埋める。続く `0x314` bytes はゼロ初期化される。

伸長ハンドラーの引数は `{相対ソース位置, 圧縮長とフラグ, 展開先}` の 3 個の u32。
圧縮長は 2 番目の値を右に 1 bit シフトして得る。
最下位 bit が 1 の場合、コード上は展開先に `r9` を加えるが、今回の全サンプルは 0。
ゼロ初期化でも宛先の最下位 bit による `r9` 相対指定がある。これらの相対指定はツールでは未対応。

## 圧縮方式

同一の 120-byte の Thumb 伸長ルーチンが 14 アプリすべてにある。
処理はリテラルコピーと既出出力への後方参照を組み合わせる LZ 系。
一般的な ZIP / zlib のヘッダーはなく、方式名を特定できていないため、ここでは命令の動作を記述する。

トークン `t` を 1 byte 読むと、以下の順で処理する。

1. リテラル数を求める。`t & 3` が 0 以外なら `(t & 3) - 1`。
   0 なら次の 1 byte を読み、その値に 2 を足す。
2. マッチ長の値 `m = t >> 4` を求める。15 なら次の 1 byte に 15 を足す。
3. 指定数のリテラルを入力から出力へコピーする。
4. `m == 0` なら後方参照はない。
5. それ以外では距離の下位 8 bit を入力から読む。上位値は `(t >> 2) & 3`。
   上位値が 3 なら追加の 1 byte を読んで置き換える。
6. `distance = low | (high << 8)` とし、出力の `distance` bytes 前から `m + 2` bytes をコピーする。
   コピー元と先の重なりを許すため、1 byte ずつコピーする。

入力の終了位置は初期化テーブルに指定された圧縮長で判断する。
独立した伸長後サイズやチェックサムはこの引数にはない。
ツールでは入力境界・後方参照・直後のゼロ領域への重なりを検証する。
展開の成立だけでは、元データの完全性を保証できない。SDU 側のチェックサム検証とは別のもの。

## 他の `.bin` と未解明の点

- `DicMain.bin` は同系統の先頭命令を持つが、初期化テーブル全体の対応は未実装。
- `SharpLib.bin` も ARM コードから始まり、先頭は `PUSH {r12, lr}` → `BLX` → `POP` → `B`。
  AppMain とは異なるエントリーであり、ライブラリの関数表・ABI は未解明。
- `data.bin` や `display.bin` などはアプリのリソース。拡張子 `.bin` だけでは実行形式を判定できない。
- `SHARP:DICT:PW-TC980` は一部アプリ内部の文字列であり、ファイル先頭のマジックではない。
  この文字列だけから対象機種を判定しない。
- API の呼び出し規約、ローダーが許容するイメージの条件、署名や再配置処理の有無は未確認。
- テーブル構造は scatter-loading に似るが、特定のコンパイラやリンカーのバージョンは断定できない。

## ツールで再現する

```sh
cargo run -p brain-app-analyzer -- \
  target/rom-dump/packages/001/ROM/App/RomanTyping/AppMain.bin \
  --data-output target/roman-data.bin
```

標準出力に JSON の解析結果、指定した新規ファイルに RAM 初期値を出力する。
元の AppMain は変更しない。コードとゼロ領域を結合した実行ファイルは生成しない。
対応する起動コード・ハンドラーと一致しないバイナリはエラーにする。

逆アセンブラへ渡すときは ARM little-endian の raw binary とし、エントリーを ARM 状態で設定する。
Thumb 初期化処理・各ハンドラーは別途 Thumb 状態として指定する。
RAM 初期値を解析する場合は `data_address` に別領域として配置する。
